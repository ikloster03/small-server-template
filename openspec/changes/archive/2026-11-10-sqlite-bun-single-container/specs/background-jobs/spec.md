## ADDED Requirements

### Requirement: Постановка задач в очередь

Система ДОЛЖНА (MUST) позволять ставить фоновые задачи: тип задачи (`kind`) и JSON-полезная нагрузка (`payload`). Задачи ДОЛЖНЫ (MUST) храниться в той же встроенной БД, что и основные данные, и переживать рестарт процесса. Каждая задача ДОЛЖНА (MUST) иметь статус из множества `pending`, `running`, `done`, `failed`, счётчик попыток и время следующего запуска.

#### Scenario: Постановка задачи

- **WHEN** код ставит задачу с типом и payload
- **THEN** в БД появляется строка задачи со статусом `pending` и временем следующего запуска

#### Scenario: Переживание рестарта

- **WHEN** процесс рестартует при наличии невыполненных задач
- **THEN** задачи сохраняются и продолжают обрабатываться после старта

### Requirement: Обработка задач воркером

Воркер ДОЛЖЕН (MUST) работать в том же процессе, что и HTTP-сервер, и периодически забирать из очереди задачи, чьё время запуска наступило. Захват задачи ДОЛЖЕН (MUST) быть атомарным: задача не может быть захвачена более одного раза. Успешно выполненная задача ДОЛЖНА (MUST) переходить в `done`, задача с исчерпанными попытками — в `failed` без остановки воркера.

#### Scenario: Выполнение задачи

- **WHEN** поставлена задача и воркер делает очередной проход
- **THEN** задача захватывается, обработчик выполняется, статус становится `done`

#### Scenario: Обработчик бросает ошибку

- **WHEN** обработчик задачи завершается ошибкой
- **THEN** задача не помечается `done`, счётчик попыток увеличивается, воркер продолжает работать

#### Scenario: Исчерпание попыток

- **WHEN** задача превышает лимит попыток
- **THEN** её статус становится `failed`, другие задачи продолжают обрабатываться

### Requirement: Отложенные задачи и повторы

Задача ДОЛЖНА (MUST) поддерживать отложенный запуск: исполнение не раньше заданного времени (`run_at`). Повтор неуспешной задачи ДОЛЖЕН (MUST) происходить не сразу: время следующего запуска пересчитывается с нарастающей задержкой (backoff).

#### Scenario: Отложенный запуск

- **WHEN** задача поставлена с временем запуска в будущем
- **THEN** воркер не захватывает её до наступления этого времени

#### Scenario: Backoff повтора

- **WHEN** задача завершилась ошибкой и ставится на повтор
- **THEN** время её следующего запуска отодвигается сильнее, чем при предыдущей ошибке

### Requirement: Модульность очереди

Очередь ДОЛЖНА (MUST) подключаться и отключаться как модуль приложения — одной строкой в композиции приложения, без изменения остальных модулей. Отключение модуля очереди НЕ ДОЛЖНО (MUST NOT) влиять на работу HTTP, auth и MCP.

#### Scenario: Отключение модуля

- **WHEN** модуль очереди исключён из композиции приложения
- **THEN** остальные модули работают без изменений
