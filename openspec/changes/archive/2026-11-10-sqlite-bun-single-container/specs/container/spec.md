## MODIFIED Requirements

### Requirement: Multi-stage Dockerfile

Образ ДОЛЖЕН (MUST) собираться в несколько этапов на базе Bun: установка зависимостей и сборка — на образе Bun, рантайм — Bun-образ на alpine, содержащий только прод-бандл, файлы миграций и минимальный набор файлов. Контейнер ДОЛЖЕН (MUST) работать от non-root пользователя и запускать сервер как entrypoint по умолчанию. В образе НЕ ДОЛЖЕН (MUST NOT) присутствовать Node.js и нативные модули серверной СУБД.

#### Scenario: Сборка образа

- **WHEN** выполняется `docker build`
- **THEN** образ собирается успешно и содержит бандл и миграции

#### Scenario: Запуск контейнера

- **WHEN** контейнер запускается с валидным `DATABASE_PATH`
- **THEN** сервер стартует от non-root пользователя без дополнительных аргументов

### Requirement: Наличие и валидность файлов контейнера

`Dockerfile` ДОЛЖЕН (MUST) существовать в корне репозитория, чтобы `docker build .` находил его без флага `-f`. `docker-compose.yml` ДОЛЖЕН (MUST) существовать и проходить `docker compose -f docker-compose.yml config` без ошибок.

#### Scenario: Сборка без явного пути к Dockerfile

- **WHEN** выполняется `docker build .` из корня репозитория
- **THEN** Dockerfile находится и используется по умолчанию

#### Scenario: Проверка compose-конфигурации

- **WHEN** выполняется `docker compose -f docker-compose.yml config`
- **THEN** команда завершается без ошибок

## REMOVED Requirements

### Requirement: Compose с локальной Postgres

**Reason**: SQLite встраивается в процесс сервера — сервис СУБД больше не нужен; compose сокращается до одного сервиса с томом под файл БД.

**Migration**: Поведение «поднимает рабочую связку одной командой» переходит в новое требование «Compose из одного сервиса». Переменные `POSTGRES_USER` / `POSTGRES_PASSWORD` / `POSTGRES_DB` и `DATABASE_URL` уходят, вместо них — `DATABASE_PATH`.

### Requirement: Compose для внешней БД

**Reason**: Внешней серверной БД в стеке больше нет — сервер работает только со встроенным файлом SQLite.

**Migration**: Файл `compose.external-db.yml` удаляется. Потребность во внешней БД возникает только при выходе за масштаб шаблона и оформляется отдельным изменением.

## ADDED Requirements

### Requirement: Compose из одного сервиса

`docker-compose.yml` ДОЛЖЕН (MUST) определять единственный сервис сервера (без службы СУБД) с томом для каталога файла БД. `docker compose up` ДОЛЖЕН (MUST) поднимать рабочий сервис: миграции применяются к файлу БД на томе, `/health` и `/ready` отвечают `200`. Старт ДОЛЖЕН (MUST) не требовать ожидания готовности внешних служб.

#### Scenario: Локальный старт

- **WHEN** выполняется `docker compose up` на свежескопированном шаблоне
- **THEN** поднимается один сервис сервера, миграции применяются, `/health` и `/ready` отвечают `200`

#### Scenario: Переживание рестарта

- **WHEN** контейнер пересоздаётся без удаления тома
- **THEN** данные (токены, задачи) сохраняются в файле БД на томе
