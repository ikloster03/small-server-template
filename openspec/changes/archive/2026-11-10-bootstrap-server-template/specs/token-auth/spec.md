## ADDED Requirements

### Requirement: Хранение bearer-токенов в Postgres

Токены ДОЛЖНЫ (MUST) храниться в таблице `tokens` со полями: `id`, `name`, `token_hash` (sha-256 секрета), `prefix` (фрагмент секрета для узнаваемости), `created_at`, `revoked_at`, `last_used_at`. В БД НЕ ДОЛЖНО (MUST NOT) храниться значение секрета. Секрет ДОЛЖЕН (MUST) генерироваться криптографически стойким генератором и отображаться ровно один раз — при создании.

#### Scenario: Создание токена

- **WHEN** выполняется создание токена с именем
- **THEN** в таблицу записывается строка с хэшем и prefix, значение секрета возвращается вызывающему один раз

#### Scenario: Повторный просмотр секрета

- **WHEN** пользователь пытается увидеть секрет существующего токена
- **THEN** значение недоступно: в БД и CLI есть только prefix и хэш

### Requirement: Bearer-middleware на защищённых маршрутах

Middleware ДОЛЖЕН (MUST) проверять заголовок `Authorization: Bearer <secret>` на защищённых маршрутах: считать sha-256 секрета и искать активный (не отозванный) токен в БД. При отсутствии или невалидности токена middleware ДОЛЖЕН (MUST) возвращать `401` с заголовком `WWW-Authenticate: Bearer`. При успехе middleware ДОЛЖЕН (MUST) обновлять `last_used_at` найденного токена.

#### Scenario: Запрос без токена

- **WHEN** защищённый маршрут вызывается без заголовка Authorization
- **THEN** ответ `401` с `WWW-Authenticate: Bearer`

#### Scenario: Невалидный токен

- **WHEN** токен в заголовке не совпадает ни с одним активным
- **THEN** ответ `401`

#### Scenario: Отозванный токен

- **WHEN** используется токен с заполненным `revoked_at`
- **THEN** ответ `401`

#### Scenario: Валидный токен

- **WHEN** используется активный токен
- **THEN** запрос выполняется, `last_used_at` токена обновляется

### Requirement: CLI управления токенами внутри контейнера

CLI ДОЛЖЕН (MUST) предоставлять команды `token list`, `token create` и `token revoke` и ДОЛЖЕН (MUST) запускаться внутри контейнера без изменения образа. `token list` ДОЛЖЕН (MUST) показывать имя, prefix, статус, даты создания и отзыва. `token revoke` ДОЛЖЕН (MUST) принимать идентификатор или имя токена и завершать его действие.

#### Scenario: list

- **WHEN** выполняется `token list` в контейнере
- **THEN** выводится таблица токенов с именами, prefix и статусами, без секретов

#### Scenario: create

- **WHEN** выполняется `token create --name ci`
- **THEN** создаётся токен и печатается секрет ровно один раз

#### Scenario: revoke

- **WHEN** выполняется `token revoke <name>` для существующего токена
- **THEN** токен перестаёт проходить проверку middleware

### Requirement: Защищённые маршруты

MCP-эндпоинт и выделенный слот API-маршрутов ДОЛЖНЫ (MUST) быть защищены bearer-middleware по умолчанию. `/health`, `/ready` и Scalar UI ДОЛЖНЫ (MUST) оставаться доступными без токена.

#### Scenario: Health без токена

- **WHEN** выполняется `GET /health` без Authorization
- **THEN** ответ `200`

### Requirement: Режим отключения auth для разработки

Переменная `AUTH_DISABLED=true` ДОЛЖНА (MUST) позволять локальную разработку без токена: middleware пропускает запросы. По умолчанию (переменная не задана) auth ДОЛЖЕН (MUST) быть включён.

#### Scenario: Локальная разработка

- **WHEN** сервер запущен с `AUTH_DISABLED=true`
- **THEN** защищённые маршруты отвечают без токена

#### Scenario: Прод по умолчанию

- **WHEN** `AUTH_DISABLED` не задан
- **THEN** защищённые маршруты требуют валидный токен
