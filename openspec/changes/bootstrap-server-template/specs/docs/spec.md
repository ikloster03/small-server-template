## ADDED Requirements

### Requirement: README на двух языках

Проект ДОЛЖЕН (MUST) содержать README на английском и русском языках (`README.md`, `README.ru.md`) с зеркальной структурой и переключателем языков в шапке.

#### Scenario: Переключение языка

- **WHEN** читатель открывает `README.md`
- **THEN** в шапке есть ссылка на `README.ru.md` и наоборот

### Requirement: Быстрый старт из шаблона

README ДОЛЖЕН (MUST) описывать путь от `Use this template` до работающего сервера: копирование, настройка env, `docker compose up`, проверка `/health`, `/ready` и Scalar UI, подключение MCP-клиента.

#### Scenario: Новый пользователь

- **WHEN** читатель следует quick start
- **THEN** он поднимает сервер локально и проверяет работу эндпоинтов и документации

### Requirement: Документация аутентификации

README ДОЛЖЕН (MUST) описывать модель bearer-токенов и команды CLI (`token list`, `token create`, `token revoke`) с примерами запуска внутри контейнера, включая предупреждение, что секрет показывается один раз.

#### Scenario: Создание токена по README

- **WHEN** читатель выполняет команду создания токена из README
- **THEN** команда выполняется в контейнере и печатает секрет

### Requirement: Документация отключения модулей

README ДОЛЖЕН (MUST) объяснять, как отключить модуль (MCP, API-слот) правкой одной строки в композиционном файле, с примером.

#### Scenario: Отключение MCP по README

- **WHEN** читатель выполняет инструкцию по отключению MCP
- **THEN** сервер перезапускается без MCP-эндпоинта

### Requirement: Паттерн вебхука для бота

README ДОЛЖЕН (MUST) содержать раздел с паттерном подключения бота через вебхук поверх того же Hono-сервера (без кода бота в шаблоне): куда добавить маршрут, как защитить его bearer-middleware.

#### Scenario: Читатель планирует бота

- **WHEN** читатель изучает раздел про вебхук
- **THEN** он понимает, какой маршрут добавить и как защитить его токеном

### Requirement: Заметка про OAuth

README ДОЛЖЕН (MUST) содержать заметку, что статический bearer достаточен для частных small-сервисов, а для публичных серверов следует рассмотреть OAuth 2.1.

#### Scenario: Публичный сервер

- **WHEN** читатель готовит публичный сервис
- **THEN** README указывает ему на необходимость OAuth вместо статических токенов
