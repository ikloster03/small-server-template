## ADDED Requirements

### Requirement: Fail-fast валидация окружения

Сервер ДОЛЖЕН (MUST) валидировать переменные окружения (`PORT`, `DATABASE_URL`, `LOG_LEVEL`, `AUTH_DISABLED`) через zod-схему до открытия порта. При невалидном или отсутствующем обязательном значении процесс ДОЛЖЕН (MUST) завершиться с ненулевым кодом и понятным сообщением об ошибке.

#### Scenario: Отсутствует DATABASE_URL

- **WHEN** процесс запускается без `DATABASE_URL`
- **THEN** процесс завершается с кодом отличным от нуля и сообщением, какая переменная невалидна
- **AND** порт не открывается

#### Scenario: Некорректный PORT

- **WHEN** `PORT=not-a-number`
- **THEN** процесс завершается с ошибкой валидации до запуска HTTP-сервера

### Requirement: HTTP-сервер на Hono

Приложение ДОЛЖНО (MUST) быть собрано на Hono и запускаться на Node.js через `@hono/node-server`. Слушающий порт ДОЛЖЕН (MUST) открываться только после успешного завершения всех шагов инициализации (env, БД, миграции).

#### Scenario: Успешный старт

- **WHEN** env валиден, БД доступна, миграции применены
- **THEN** сервер открывает порт и логирует сообщение о готовности с номером порта

### Requirement: Health-эндпоинты

Сервер ДОЛЖЕН (MUST) предоставлять `GET /health` (liveness) и `GET /ready` (readiness). `/health` ДОЛЖЕН (MUST) отвечать `200`, пока процесс жив. `/ready` ДОЛЖЕН (MUST) отвечать `200` при доступной БД и `503` при недоступной.

#### Scenario: Liveness

- **WHEN** выполняется `GET /health` на живом процессе
- **THEN** ответ `200` без обращения к БД

#### Scenario: БД недоступна

- **WHEN** выполняется `GET /ready` при недоступной БД
- **THEN** ответ `503`

### Requirement: Graceful shutdown

По сигналу SIGTERM или SIGINT сервер ДОЛЖЕН (MUST): прекратить принимать новые соединения, дождаться завершения незавершённых запросов, затем закрыть пул соединений БД и завершить процесс с кодом 0. ДОЛЖЕН (MUST) быть таймаут принудительного завершения, чтобы зависшие соединения не блокировали остановку.

#### Scenario: SIGTERM при активных запросах

- **WHEN** процесс получает SIGTERM во время выполнения запросов
- **THEN** запросы завершаются, пул БД закрывается, процесс выходит с кодом 0

#### Scenario: Зависшее соединение БД

- **WHEN** пул не закрывается в течение таймаута
- **THEN** процесс принудительно завершается

### Requirement: Логирование с request-id

Сервер ДОЛЖЕН (MUST) логироваться через pino. Middleware ДОЛЖЕН (MUST) читать заголовок `x-request-id` и генерировать новый идентификатор, если заголовка нет; идентификатор ДОЛЖЕН (MUST) попадать во все записи лога запроса и возвращаться в ответе заголовком `x-request-id`.

#### Scenario: Запрос без x-request-id

- **WHEN** входящий запрос не содержит `x-request-id`
- **THEN** middleware генерирует новый идентификатор, лог запроса содержит его, ответ включает заголовок `x-request-id`

### Requirement: OpenAPI и Scalar UI

Сервер ДОЛЖЕН (MUST) генерировать OpenAPI-спецификацию из фактических роутов Hono и отдавать UI Scalar на маршруте `/doc`. Спецификация ДОЛЖНА (MUST) соответствовать реализованным маршрутам.

#### Scenario: Открытие документации

- **WHEN** открывается `GET /doc`
- **THEN** рендерится Scalar UI со спецификацией, содержащей маршруты сервера (включая `/health` и `/ready`)
